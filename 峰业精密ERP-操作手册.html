④ 6 大业务流程操作指引

4.1 核心生产流（最长链 11 节点 · 销售发起）

路径：销售创建销售订单 → 自动生成核心生产流实例 → 节点依次流转

节点角色操作拒绝后去向
1 来货登记/销售发起SALES新建客户 → 合同 → 销售订单；同步创建来货登记回到销售修改
2 运营核对OPERATION左侧"审批中心"→ 点通过 / 驳回SALES
3 部门主管初审DEPT_HEAD待办数字徽章红点 → 通过 / 驳回SALES
4 采购询价PURCHASE原材料采购价录入采购复核
5 仓管备料WAREHOUSE领料单出库确认采购
6 厂长排产MANAGER工单下达到车间（工单页）仓管
7 生产报工MANAGER完工单提交 + 质检确认排产
8 运营复核OPERATION核对数量 / 异常返工报工
9 财务成本核算FINANCE核算工时+材料成本运营
10 总经理终审GM通过 → 进入发货财务
11 销售发货SALES发货登记（需销售最终确认，项目记忆硬约束）终审
⚠️ 销售订单可见性：只有"负责销售本人 + GM"能看到订单完整客户名；其余角色看到客户名自动打码缩写（项目记忆硬约束）。

4.2 来货登记流程

  1. 销售发起 → 自动生成"销售订单"（ReceivingLog↔Order强耦合）
  2. 运营核对（审批中心，左侧bar "check"图标）
  3. 财务入账
  4. 运营归档
  5. 全部过完 → Order状态自动变 EFFECTIVE 已生效

4.3 费用报销流程

  1. 申请人提交报销单（PR页）
  2. 部门主管初审
  3. 财务审核（金额正确性/发票）
  4. 5000元以下自动生效；>5000元自动流转到总经理终审
  5. 财务打款并标记付款（分一般纳税人/小规模）

4.4 采购请求审批

  1. 部门主管发起采购请求（含金额/供应商）
  2. 财务审核预算
  3. 执行采购：采购创建采购单 → 入库

4.5 调价申请审批

  1. 销售发现合同价/实际到款有差异时发起"调价申请"
  2. 必须由销售发起 + GM审批通过才能生效（项目记忆硬约束）
  3. 审批后：财务到账登记会联动差额

4.6 完工单确认

  1. 厂长提交完工单 + 上传QC质检报告
  2. 质检确认（厂长自确认/运营抽检）
  3. 运营归档入完工库

⑤ AI 数据分析模块（DeepSeek 双模型架构）

架构：两步调用，绝不虚构数据（项目记忆硬约束）

  用户自然语言 ─► 第1步 deepseek-v4-flash 意图解析 (便宜快) ─► 解析出 pivot 参数 JSON
                                                              │
                                                              ▼
                                              后端跑SQL聚合得到真实数据(纯数字)
                                                              │
                                                              ▼
                  报告前端渲染 ◄── 第2步 deepseek-v4-pro 生成报告(强+贵) ◄────┘
                                                              ↑
                                                     所有数字必须是传入聚合结果
                                                     (禁止LLM编造/预测/假设)

DeepSeek 环境变量配置（必须填才能启用）

变量名示例值必填说明
DEEPSEEK_API_KEYsk-f6c5d24xxxxxxxxxxxxxxxx✅ 是控制台生成的 key；不填 → AI模块禁用
DEEPSEEK_BASE_URLhttps://api.deepseek.com✅ 是走中转折填中转域名（注意：不用手动加 /chat/completions，系统智能拼接）
DEEPSEEK_MODEL_FASTdeepseek-v4-flash默认意图解析用，便宜、快
DEEPSEEK_MODEL_PROdeepseek-v4-pro默认报告生成用，强

调用路径智能拼接（20260811-11版新增）

兼容 3 种填写方式，不会出现 /chat/completions/chat/completions 重复拼接：

  1. 裸域名：https://api.deepseek.com → 自动补 /chat/completions
  2. 带v1：https://api.deepseek.com/v1/ → 自动补 /chat/completions（末尾斜杠会被去）
  3. 完整路径：https://中转域名/xxx/chat/completions → 直接原封使用

意图解析失败回退（项目记忆硬约束）

LLM 意图解析失败不会白屏/崩 → 自动回退到"关键词匹配"（例："本月销售"→dataset=orders agg=sum metric=total_amount）。

数据集白名单校验（项目记忆硬约束）

LLM 输出的 dataset / rows_dim / cols_dim / metric 必须命中后端 dataset_rows_metric_whitelist；否则拒绝跑 SQL + 报错给用户（防注入/越权）。

⑧ Zeabur Docker 部署 & 502 终极排障手册

1) GitHub 仓库 Push 最新 master
2) Zeabur 控制台 → New Project → Deploy from GitHub → 选中 don508xx-ui/liu-erp
3) 选根目录, 构建类型 Dockerfile, Zeabur会自动找到 Dockerfile
4) ⚠️【最关键】进入该服务 → Variables/Environment Variables, 粘贴下方环境变量:

环境变量（复制直接贴进变量框）

PASSWORD=Hb61xJiV5CLPhn329QouRI75KeW04wf8
PORT=8000
JWT_SECRET=zeabur-prod-change-me-please-use-long-random-string-32chars+
JWT_TTL_MINUTES=1440
DB_DRIVER=sqlite
DB_URL=sqlite:////app/data/erp.db
PYTHONUNBUFFERED=1

DEEPSEEK_API_KEY=sk-你自己的真实Key
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL_FAST=deepseek-v4-flash
DEEPSEEK_MODEL_PRO=deepseek-v4-pro
🚨 致命错误清单 —— 出现502 99% 都是其中之一：
  1. 手填 PORT=${WEB_PORT} → Zeabur环境变量框不做shell变量替换，这会把PORT变成字面量字符串"${WEB_PORT}"，uvicorn 绑定直接崩。必须写 PORT=8000。
  2. 健康检查路径写死 / → 冷启动阶段静态文件挂载慢会导致首探失败，循环崩。必须写 /health。
  3. 不填 DEEPSEEK_API_KEY → AI功能直接报错"DEEPSEEK_API_KEY 未配置"，但不影响其他业务。
  4. GitHub连通失败 → 用国内代理：https://gh-proxy.com/https://github.com/don508xx-ui/liu-erp.git

健康检查设置（Settings → Health Check）

字段正确值为什么
TypeHTTP我们提供纯JSON /health端点
Path/health探活零依赖（不读DB/不读静态，<1ms返回）
Port8000EXPOSE端口
Startup Delay90 秒pandas + SQLAlchemy + 冷DB建表 + 种子数据要时间
Interval15 秒
Timeout5 秒
Retries10 次90 + 15*10 = 240秒 启动窗口，够冷柜启动

502 诊断顺序（按图索骥）

  1. 先看 Build 日志：有没有 ERROR: Could not find a version 或 pip install 失败？（requirements.txt漏包）
  2. 再看 Runtime 日志里有没有：
    • [BOOT] resolved PORT=8000 (raw='${WEB_PORT}') → 环境变量写坏了，修正PORT=8000 并 Redeploy
    • 看不到 Uvicorn running on http://0.0.0.0:8000？→ 找上几行的 Python Traceback（通常是 import 错误）
  3. 如果日志显示 Application startup complete 但浏览器仍502：
    • → 健康检查路径 UI 里仍为 "/" 而不是 /health（改UI设置）
    • → Pod还在 CrashLoopBackOff → kubectl describe 等价面板里看OOM/磁盘（本ERP内存≈150MB，basic足够）
  4. 临时替代方案（最快）：本地跑服务 + 开 localtunnel： 
    本地:  python -m uvicorn app.main:app --host 0.0.0.0 --port 8001
另开终端:  npm i -g localtunnel --registry=https://registry.npmmirror.com
